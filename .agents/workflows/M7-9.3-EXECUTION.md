# M7-9.3 — ACME Agent Execution Contract

## Status

Implementation present on `main`.

## Execution boundary

An execution request is independently validated against the registered agent before execution. The engine verifies identity/version, authorization, declared capabilities, declared tools, data classes, execution limits, human-approval requirements, provenance and audit requirements.

## Runtime guarantees

- Fail closed on malformed requests and unregistered/mismatched agents.
- Reject undeclared capabilities and tools.
- Reject requests exceeding registered limits.
- Require human approval when the execution contract requires it.
- Require provenance and audit recording for every execution outcome, including blocked outcomes.
- Propagate an `AbortSignal` and convert execution timeout to `timed_out`.
- Validate structured results and output-size limits.
- Distinguish `succeeded`, `partial`, `blocked`, `failed`, `cancelled`, and `timed_out` outcomes.

## Acceptance tests

`api/runtime/execution-engine.test.js` covers authorized execution, undeclared tools, missing human approval, timeout/abort, malformed results, limit escalation and governance recording for blocked outcomes.
